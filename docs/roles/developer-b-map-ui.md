# 개발자 B 역할 계획: 3D 지도·UI

- 브랜치: `dev-b`
- 한 줄 요약: 3D 지도 위에 안전·주의·위험 구역과 포인트를 그리고, 사용자가 10초 안에 "언제, 왜 위험한지" 이해하는 화면을 만든다.
- 상대: 개발자 A는 점수와 원인을 계산해 API와 타일로 내준다(`docs/roles/developer-a-data-risk.md`).

## 요구사항 재정리

PRD의 MVP 기능 네 개 중 B가 책임지는 부분이다.

| PRD 기능 | B의 책임 |
| --- | --- |
| F1. 위성·지형 기반 환경 분석 | 표시만. 지형 요약을 포인트 상세에 보여 준다 |
| F2. 포인트별 위험도 표시 | 화면 전부. 등급 배지, 원인 상위 3, 시간대별 위험 띠, 수집 시각과 신뢰도 |
| F3. 3D 낚시 지도 | 전부. 3D 지형, 위험 구역 레이어, 핀, 시간 슬라이더, 레이어 토글, 2D 전환 |
| F4. 안전 낚시 장소 추천 | 화면 전부. 추천 목록, '더 안전한 곳 추천' 흐름 |

디자인 시스템은 Material 3다(프로젝트의 Material 3 Design Kit 기준). 화면 구성은 PRD의 "메인 화면 UI/UX" 절을 따른다.

## 단계별 계획

### 0단계. 앱 골격 (가장 먼저, A보다 앞서 `ship`)

1. 저장소 루트에 Next.js(App Router, TypeScript) 프로젝트를 만든다. 하위 폴더를 만들지 않는다.
2. `package.json`에 `lint`, `typecheck`, `build` 스크립트를 둔다. `ship`이 이 이름을 찾아 실행한다.
3. Material 3 토큰을 `styles/tokens.css`에 CSS 변수로 정의한다. 색 역할(primary, surface, error 등), 글자 크기 단계, 모서리, 높이.
   등급용 확장 색 `safe`(녹색 계열), `caution`(황색 계열)을 추가하고 `danger`는 `error` 역할을 쓴다.
4. 기본 레이아웃을 만든다. 넓은 화면은 Navigation rail, 좁은 화면은 Navigation bar.

- 완료 기준: 빈 지도 자리와 내비게이션이 있는 첫 화면이 뜨고 `npm run build`가 통과한다. 바로 `ship` 한다.
- 주의: 이 `ship`이 끝나야 A가 `lib/contract/`와 `app/api/`를 추가할 수 있다. 가장 먼저 끝낸다.

### 1단계. 지도 기본 (A의 환경 분석과 같은 시기)

1. MapLibre GL JS 지도를 띄우고 카메라를 뉴포트(대략 북위 44.63°, 서경 124.06°)에 맞춘다.
2. 3D 지형을 켠다. A의 지형 타일이 나오기 전에는 공개 데모 지형 타일로 개발하고, 주소는 환경 변수 `NEXT_PUBLIC_TERRAIN_TILES_URL`로 바꿀 수 있게 한다.
3. `lib/contract/fixtures/spots.json`으로 포인트 핀을 그린다. 핀은 색과 모양(안전 원, 주의 삼각형, 위험 팔각형)과 글자로 등급을 구분한다.
4. 데이터 불러오기 훅을 만든다. 환경 변수 `NEXT_PUBLIC_USE_FIXTURES=0`이면 실제 API를, 그 밖에는 예시 데이터를 쓴다(A의 API가 나올 때까지 예시 데이터가 기본값).

- 완료 기준: fixtures만으로 지도에 핀 세 종류가 보이고, 회전·기울이기·확대가 된다.

### 2단계. 위험도 화면 (F2)

1. **포인트 상세 시트.** 넓은 화면은 Side sheet(폭 360dp), 좁은 화면은 Bottom sheet 3단(접힘: 등급 한 줄, 중간: 원인 상위 3, 펼침: 전체).
   내용: 포인트명, 접근 정보, 등급 배지, 원인 상위 3, 시간대별 위험 띠, 지형 요약, 수집 시각과 신뢰도, 안전 고지.
2. **시간 슬라이더.** 지금부터 +72시간, 1시간 단위, 재생 버튼. 움직이면 핀·시트가 함께 바뀐다.
3. **화면 상태.** 기본(선택 없음), 선택됨, 불러오는 중(뼈대 화면), 데이터 지연(`stale`), 지원 범위 밖(`OUT_OF_COVERAGE`), 오류.
4. A의 실제 API가 나오면 fixtures에서 전환한다.

- 완료 기준(게이트 2 기여): 핀을 누르고 10초 안에 등급과 원인을 읽을 수 있다. 여섯 가지 상태가 모두 화면으로 확인된다.

### 3단계. 3D 지도 완성 (F3)

1. **위험 구역 레이어.** `NEXT_PUBLIC_ZONES_PMTILES_URL`의 `zones` 레이어를 지형 위에 덮고, `GET /api/zones/grades` 응답으로 색을 칠한다.
2. **레이어 토글.** 위험 구역, 경사, 과거 침수 흔적, 위성 영상.
3. **2D 전환과 대체 경로.** 2D·3D 전환 버튼. WebGL을 쓸 수 없으면 2D로 자동 전환하고 한 번만 알린다.
4. **반응형.** 600dp 미만, 600~839dp, 840dp 이상 세 구간.
5. **성능.** 시간 슬라이더를 끌 때 요청을 묶고(디바운스), 이미 받은 시각은 다시 받지 않는다.

- 완료 기준(게이트 3): 중급 휴대폰 브라우저에서 지도 조작이 끊기지 않는다. 첫 화면에서 지도 조작 가능까지 4초 이내(휴대폰 4G 기준).

### 4단계. 추천과 마무리 (F4)

1. **추천 목록.** 포인트를 고르지 않았을 때 오른쪽 시트에 추천 5곳을 보여 준다. 항목: 포인트명, 등급, 이유 한 줄.
2. **'더 안전한 곳 추천'.** 위험 포인트에서 누르면 `excludeSpotId`를 넣어 추천을 받고 목록으로 바꾼다.
3. **검색과 필터.** Search bar, 장소 유형 Filter chips, '안전만 보기'.
4. **접근성.** 터치 대상 48dp 이상, 글자 대비 4.5:1 이상, 키보드로 핀 이동, 등급과 원인을 스크린 리더가 읽음.
5. **고지와 출처.** 모든 등급 옆에 안전 고지 문구. 설정 화면에 데이터 출처 목록, 지도 하단에 "Weather data by Open-Meteo.com" 링크.

- 완료 기준(게이트 4): 처음 쓰는 사람이 3번 이하의 조작으로 위험 원인을 확인한다. 추천 목록만으로도 지도와 같은 정보를 얻을 수 있다.

## 검증 기록 (2026-11-24)

배포용 빌드(`npm run build` 후 `next start`)를 Chrome에서 휴대폰 조건으로 측정했다.
조건: 화면 375×812, 네트워크 Fast 4G, CPU 4배 감속, 캐시 비움, 예시 데이터.

| 항목 | 결과 | 기준 |
| --- | --- | --- |
| 지도 조작 가능까지 걸린 시간 | 2.8초, 1.8초 (2회) | 4초 이내 |
| 화면 첫 표시(LCP) | 1.0초 | 참고 |
| 레이아웃 흔들림(CLS) | 0.00 | 참고 |
| 접근성 점수, 지도 화면 | 96 (수정 전 91) | 참고 |
| 접근성 점수, 추천·설정 화면 | 100, 100 | 참고 |
| 등급 글자 대비, 밝은 테마 | 5.1 ~ 6.5 : 1 | 4.5 : 1 이상 |
| 등급 글자 대비, 어두운 테마 | 6.3 ~ 8.2 : 1 | 4.5 : 1 이상 |

- 지도 조작 가능 시점은 `performance.mark('map-ready')`로 잰다. 브라우저 콘솔에서 `performance.getEntriesByName('map-ready')[0].startTime`으로 다시 확인할 수 있다.
- 이 측정으로 고친 것: 검색창과 레이어 버튼의 잘못된 `aria-controls`, 주의 등급 색의 대비 부족(4.2 → 5.4), 어두운 테마에서 등급 글자가 안 보이던 문제.
- 지도 화면에 남은 접근성 실패 1건은 가까운 핀끼리 터치 영역이 겹치는 것이다. 핀 위치는 실제 지리 위치라 옮길 수 없고(WCAG 2.5.8의 필수 표시 예외), 추천 화면의 목록이 대체 경로다. 겹칠 때는 더 위험한 핀이 위에 오게 했다.
- 한계: 에뮬레이션은 실제 휴대폰의 그래픽 성능을 재현하지 못한다. 지도를 끌 때의 끊김은 실제 기기에서 확인해야 한다. 지형과 구역이 A의 실제 타일로 바뀌면 다시 측정한다.

## 진행 기록 (2026-11-24)

예시 데이터로 0~4단계의 화면을 모두 만들었다. 아래는 계획과 다르게 했거나 남은 일이다.

- 타입은 A의 `lib/contract/types.ts`를 쓴다. 임시 타입 파일(`lib/ui/api-types.ts`)은 지웠다.
- 예시 데이터는 두 가지다. 기본은 시간에 따라 변하는 시뮬레이터(`lib/ui/dev-fixtures.ts`)이고, 주소에 `?demo=contract` 또는 `?demo=contract-empty`를 붙이면 A의 예시 응답(`lib/contract/fixtures`)을 그대로 보여 준다.
  A의 예시는 한 시각의 고정된 응답(포인트 4곳, 시간대 2~3개)이라 시간 슬라이더를 움직여 볼 수 없어서 시뮬레이터를 남겼다. 실제 API가 연결되면 시뮬레이터는 지운다. 좌표, 이름, 점수는 모두 예시다.
- 위험 구역은 포인트 주변의 임시 원이다. `NEXT_PUBLIC_ZONES_PMTILES_URL`을 넣으면 A의 타일을 쓴다.
- 지형은 공개 지형 타일(AWS의 Mapzen Terrain Tiles)이다. `NEXT_PUBLIC_TERRAIN_TILES_URL`을 넣으면 A의 타일을 쓴다.
- 3D 보기는 지형 고도 위에 실제 항공 사진을 입힌 것이다. 처음에는 밝은 평면 지도를 기울인 것뿐이라 입체감이 없었고, 사용자 요청("구글어스처럼 실제 지형")에 따라 바꿨다.
  항공 사진은 USGS The National Map의 공개 타일(퍼블릭 도메인, 키 불필요, 미국만 제공, 확대 16단계까지)이다. 지형 높낮이는 1.6배로 과장해 보여 준다(`lib/map/config.ts`의 `VIEW_3D`).
  다른 나라로 넓히려면 `NEXT_PUBLIC_SATELLITE_TILES_URL`에 다른 타일 주소를 넣어야 한다.
- 건물과 절벽까지 입체로 보이는 구글어스 수준(사진 측량 3D)은 아니다. 그 수준은 Google Photorealistic 3D Tiles가 필요하고, API 키와 결제 계정, 지도 엔진 교체(CesiumJS 등)가 따른다.
- 실시간 레이어 네 개를 넣었다(사용자 요청, Ventusky·Windy·earth.nullschool 참고). 모두 키 없이 쓰는 공개 데이터이고 코드는 `lib/map/live.ts`, 출처 주소는 `lib/map/config.ts`의 `LIVE`에 있다.
  - 바람 흐름: Open-Meteo의 현재 풍속·풍향을 7×7 격자로 받아 흐르는 입자로 그린다. 기본으로 켜져 있다.
  - 파고: Open-Meteo Marine의 현재 파고를 경계선 없는 색 그라데이션으로 그린다. 격자(0.3°, 약 25~30 km) 사이를 이어 붙인 그림을 지도에 올리고, 해안에서는 옅어지게 한다. 격자가 성겨 해안선 위치는 대략적이다.
  - 위험 구역: 윤곽선을 긋지 않는다(사용자 요청). 실제 구역 도형이 없는 지금은 포인트를 중심으로 바깥으로 갈수록 옅어지는 색(반지름 약 600 m)으로 그리고, 실제 도형(PMTiles)이 오면 가장자리를 넓게 흐려 그린다.
  - 강수 레이더: 미국 NEXRAD 합성 타일(아이오와 주립대 IEM). 미국만 나온다.
  - 위성 구름 영상: NASA GIBS의 GOES-West 영상(확대 7단계까지).
  - 파고·레이더·구름은 넓게 봐야 보여서, 켜면 지도가 광역으로 물러난다.
  - 바람·파고는 브라우저가 Open-Meteo를 직접 부른다(15분 캐시). 방문자가 늘면 무료 한도와 비상업 조건이 문제가 되므로, 운영 전에 A의 서버가 모은 값을 받도록 바꿔야 한다.
- 구역·핀의 등급은 실제 데이터로 계산한다. 처음에는 가상의 날씨로 계산해서, 실시간 파고가 4 m인 곳에 '안전'이 표시되는 모순이 있었다(사용자 지적).
  지금은 `lib/ui/dev-fixtures.ts`가 Open-Meteo의 72시간 예보와 미국 기상청(NWS)의 발효 중 경보를 받아 A의 위험도 모델(`lib/risk`의 `computeHourlyRisk`)에 넣는다. 경보가 발효 중이면 PRD 규칙대로 모든 포인트가 '위험'이 된다.
  아직 예시인 것은 포인트의 좌표·이름·지형 점수다. 실제 예보를 6초 안에 못 받으면 가상의 날씨로 대신한다.
- '경사' 레이어는 지형 음영으로 대신했다. '과거 침수 흔적' 레이어는 타일 주소가 없어 꺼 둔 상태로 보인다.
- WebGL을 쓸 수 없는 기기에서는 2D 지도 대신 포인트 목록을 보여 준다. 지도 엔진 자체가 WebGL을 필요로 해서다.
- deck.gl은 쓰지 않았다. 구역과 핀은 MapLibre만으로 충분했다.
- 내비게이션은 지도, 추천, 설정 세 개다. '저장'은 MVP 포함 여부가 정해지지 않아 넣지 않았다.
- 검색은 포인트 이름과 장소 유형만 찾는다. 지명 검색은 넣지 않았다.
- Material 3 컴포넌트 라이브러리는 쓰지 않고 토큰(CSS 변수)과 직접 만든 컴포넌트로 구성했다. 색은 Material 3 기본 색 구성표다.
- 화면 상태는 주소에 `?demo=stale`, `?demo=error`, `?demo=coverage`, `?demo=slow`, `?demo=contract`, `?demo=contract-empty`를 붙여 확인할 수 있다(예시 데이터일 때만).
- 지도 엔진의 작업자 파일은 `npm install` 때 `public/maplibre-gl-worker.mjs`로 복사된다(`package.json`의 `postinstall`).
- 화면 점검으로 고친 것(넓은 화면 1366, 중간 714, 휴대폰 375 폭에서 확인):
  - 발효 중인 경보를 지도 위 칩과 추천 목록의 빈 상태에 보여 준다. 전에는 포인트 상세에만 있어서, 전 포인트가 '위험'인 이유를 지도에서 알 수 없었다.
    경보는 목록의 첫 포인트 상세에서 읽는다(`useRegionAlerts`). 포인트 목록 응답에 넣어 달라고 A에 요청해 두었다.
  - 실시간 칩을 "일대 실시간 · 바람 · 앞바다 파고"로 고치고, 상세 시트에 포인트 예보와 값이 다른 이유를 적었다.
  - 필터 칩이 넓은 화면에서 잘리지 않게 했고, 범례는 좁은 화면에서 왼쪽으로 옮겼다(오른쪽 지도 컨트롤에 가려졌다).
  - 접힌 시트의 높이를 제목과 부제에 맞췄다. 포인트를 골라 이동하면 출처 표기가 (i) 버튼으로 접힌다(지도를 끌 때와 같은 동작).
  - 추천 화면은 72시간을 1시간 단위로 고를 수 있고, 안내 문구가 그 화면의 조작과 맞는다.
